Done when:
  - attach copies source_path into evidence/<code>/<date>_<slug>.<ext>, where
    the date is the SOURCE file's mtime and the name comes from core.slugify
    over the source stem and extension (C3.2 frozen guarantee).
  - collision handling: a second file producing the same destination name
    appends _2, then _3, BEFORE storing. The stored rel_path is what the row
    carries. A test attaches three files that slugify identically and asserts
    the three rel_paths and that all three files exist on disk.
  - the row is the truth of where the file is: a test reads the row's
    rel_path and asserts a file exists at that path with a matching sha256.
  - the EVIDENCE event is emitted, and its summary contains the file name.
  - raises, each with the file NOT copied and NO row written (assert the
    evidence directory is unchanged in every case):
      UnknownProjectService  unknown project_code
      EvidenceConflict       rel_path already recorded
      MissingFileError       source_path unreadable
      InvalidSlug            the source name cannot be slugified
  - no size cap: a 1 MB fixture attaches without error (C3.2 says a large
    file must never raise; 1 MB proves the absence of a cap without a slow
    test).
  - open_path returns an ABSOLUTE path and validates first: raises PathEscape
    for a rel_path outside the project, MissingFileError if absent.
  - list_for returns the project's rows, newest first.
  - ServiceKit(root).evidence is real.

Forbidden: exposing an absolute path in anything but open_path's return
  value; normalising or rewriting rel_path after it is stored; deleting any
  file — removal is not in C3.2; enforcing a size cap.
