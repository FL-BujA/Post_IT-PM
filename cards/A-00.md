# PORTION A-00 — data: assemble the DataKit repository slots (C2.1)

Goal: C2.1 specifies that DataKit is the ONLY thing services/ may call, and
lists eleven attributes it must expose:

    projects, events, cycles, gates, actions, evidence,
    minutes, signals, reports, search, integrity

The built DataKit exposes none of them. It has __init__, tx and close, and
every repository is constructed directly by its caller with a _KitLike object.
The card that closed the data contract asserted repository behaviour, not the
kit's shape, so the divergence went unnoticed.

This card assembles the kit. It is additive: every repository keeps its
current constructor and everything that builds a repo directly keeps working.
This must land before any service card can delegate through the kit.

Contract: 02-CONTRACTS-data.md (C2.1)

Files allowed (R10 budget: 2 source files + their tests):
  SOURCE  data/db.py
  TESTS   tests/data/test_datakit.py

Context Pack: this card · the C2.1 code block of contracts/02-CONTRACTS-data.md,
  which lists the eleven attributes verbatim · core.sig.txt for every
  repository class and its __init__ signature. Every repo takes a single
  kit-like argument; DataKit itself satisfies that protocol. Do not open any
  .py file under data/ other than db.py.

Done when:
  - DataKit exposes all eleven C2.1 attributes, each returning the
    repository C2.1 names for it, constructed with the kit itself.
  - construction is lazy and cached: accessing kit.projects twice returns the
    SAME instance (assert identity), and a DataKit that is never asked for a
    repo constructs none. Lazy because IntegrityService and SearchRepo are
    heavier than the rest and most callers touch two or three slots.
  - test_c21_attribute_set — the eleven names are transcribed from the
    contract into the test as a tuple, and the test asserts each attribute
    exists and is an instance of the class C2.1 names for it. This is the
    assertion whose absence let the divergence stand.
  - tx, close and __init__ behave exactly as before; the existing db tests
    pass with their intent intact.
  - every repository's own constructor is unchanged, and code that builds a
    repo directly still works — one test constructs a repo the old way and
    the new way against the same db and asserts both read the same row.

Forbidden: changing any repository's constructor or methods; making the
  slots eager; adding a twelfth attribute (a new slot is a CC card); editing
  anything under contracts/.

Stop and ask if: a class C2.1 names is absent from core.sig.txt, or its __init__ takes something other than a single kit-like argument. Report which one and stop — do not adapt the repository to fit.
